# Contributing

This repo uses a standard branch + Pull Request flow. `main` is protected —
no direct pushes, no force pushes, and every change lands via a reviewed PR.

## Workflow

1. Branch off an up-to-date `main`:

   ```bash
   git switch main && git pull
   git switch -c <type>/<short-description>   # e.g. feat/replicate-averaging
   ```

   Common prefixes: `feat/`, `fix/`, `refactor/`, `docs/`, `chore/`.

2. Make your changes, following the existing style in the file you're
   touching (naming, comment density, quoting conventions).

3. Before opening a PR, run locally what CI will check:

   ```bash
   shellcheck scripts/**/*.sh          # or your editor's shellcheck integration
   ruff check .
   bash -n scripts/**/*.sh references/*.sh   # syntax-only sanity check
   ```

4. Push and open a PR against `main`:

   ```bash
   git push -u origin <your-branch>
   gh pr create --base main --fill      # or via the GitHub website
   ```

   Fill in the PR template — it's short on purpose.

5. A PR needs:
   - **1 approval** (from a Code Owner, once your change touches an area
     listed in `.github/CODEOWNERS`).
   - **CI passing** (shellcheck, ruff, and a bash syntax check).
   - **All review conversations resolved.**

6. Merge method is **Squash and merge** — your branch's commit history
   doesn't need to be clean, but write a good final commit message (or
   clean up the suggested squash message) since that's what lands on `main`.

## Code style notes

- Shell scripts: `set -uo pipefail` (not `-e`, when a script processes rows
  independently and one bad row shouldn't kill the whole run), and match
  the logging/error-handling helpers already in `scripts/lib/common.sh`
  rather than rolling your own.
- Python: follow `ruff.toml` (currently `E`, `F`, `B` rule sets, 100-char
  lines). Run `ruff check .` before pushing.
- Never hand-write a `configs/*.local.csv`/`artifacts/**/*.local.csv` — those
  are generated by `scripts/generate_configs.py`. If you need a new example,
  add it to `artifacts/examples/` instead.
- Don't commit real data, credentials, or machine-specific absolute paths.
  Check `.gitignore` covers any new local-only file/folder pattern you add.
